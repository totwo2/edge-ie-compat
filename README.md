# Edge IE 兼容管家（edge-ie-compat）

**版本 v1.0.0（首次发布）**

**一句话**：让同事的老旧内网站点在 Edge 里用 IE 引擎正常打开——你只管给网址，AI 帮你试出该用哪个 IE 版本，调好一键导出 `.bat` 给全组直接复用。

## 适合谁

- 公司还有 OA、财务、工控等只能跑在 IE 内核的老系统。
- 想把这些站点加进 Edge 的 IE 兼容模式（Enterprise Mode / IE mode）。
- 一个人调通后，要把同一批站点的配置发给同事直接用。

## 三件事它帮你做

1. **引导式试版本**：老系统到底吃 IE8 / IE9 / IE11 哪个内核，谁也说不准，只能实测。AI 按 IE9 → IE8 → IE11 顺序替你逐个试，你只要看页面能不能正常用，回一句「能用 / 不行」。
2. **增删改查站点**：用大白话让 AI 加站点、删站点、改文档模式、列清单，结论一句总结给你留存。
3. **一键导出 `.bat`**：调好后跑一次生成器，产出 `setup-ie-compat.bat`，以管理员运行即把站点写进 Edge 企业模式列表 + Intranet 区域 + ActiveX 策略，重开 Edge 就生效。把这份 `.bat` 发给同公司同事，他们同样以管理员运行即可。

## 30 秒上手

1. 把 skill 目录里的 `sitelist.xml.example` 复制成 `sitelist.xml`，把里面的占位假域名 `intranet.example.com:7001` 换成你的真实内网站点（可一次列多个）。
2. 在 skill 目录运行生成器：

```
cd ~/.workbuddy/skills/edge-ie-compat
python3 gen.py
```

3. 把生成的 `dist/setup-ie-compat.bat` 在 Windows 上右键「以管理员身份运行」，重开 Edge，打开老系统看能不能用。
4. 不知道该用哪个版本？直接把网址丢给 AI，走下面的引导测试。

## 引导式 IE 版本测试（老站点必走）

1. 给 AI 网址（带端口），并说一句是否大概知道要哪个版本。
2. AI 默认按 IE9 → IE8 → IE11 取第一个写进 `sitelist.xml`，跑生成器，把 `.bat` 路径给你。
3. 你这边：保存 Edge 里没保存的内容 → 运行 `.bat` → 重开 Edge → 打开该站点，按下面的清单看一眼。
4. 回 AI「能用 / 不行」：
   - 能用 → 锁定该模式，调试完成。
   - 不行 → AI 换成下一个内核重生成，再测，直到通过或三个都试完。
5. 多个站点逐个走这套；同一套系统 / 同技术栈的站点，可先测一个代表站再套用其余。

> ⚠️ 把 `.bat` 交给你之后，AI 会停下来等你的实测反馈，不会自己假定成功往下走——这是避免整套调试静默失败的关键。

### 怎么算「能用」（挑最常用的功能试：登录 / 查询 / 提交）

| 算能用 | 算不行 |
|---|---|
| 页面能打开，不白屏 | 白屏 / 一直转圈 / 无法显示网页 |
| 能正常登录 | 提示缺插件或控件 / 弹「此网站需要 Internet Explorer」 |
| 常用按钮点得动、有反应 | 点了没反应 / 提交不了 / 数据加载不出 |
| 表格和文字显示正常、不乱版 | 布局错乱 / 字变大变小 / 图片裂开 |

### 三个模式都试完还不行（兜底）

- 本工具只支持 IE8 / IE9 / IE11 三种文档模式；IE7 及更老内核不在范围内，怀疑更老内核请走 IT 或系统开发商。
- 可试：检查是否缺 Java 插件或旧版 IE 组件、是否需要 32 位 IE、在 IE「兼容性视图」里加该站点、联系开发商确认技术栈。
- 仍提示「缺插件 / 控件」且确认已是 IE 模式，可能是依赖未标记为安全的 ActiveX（生成脚本默认禁用，是偏保守的安全设置）。这属可信内网站点才放开的安全取舍——遇到时让 AI 重新生成放开即可，你无需手改 `.bat`。

## 管理站点（增 / 删 / 改 / 列清单）

所有站点存在 `sitelist.xml`（唯一真源）。让 AI 用大白话操作：

- **加**：给网址 + 模式（或直接走引导测试），AI 在 `<site-list>` 内追加一行，`version` 由生成器自动 +1，你不用管。
- **删**：AI 删对应的 `<site>` 行，重跑生成器。
- **改**：AI 改该行 `<compat-mode>`，重跑生成器。
- **列**：AI 读 `sitelist.xml`，把当前站点 + 模式念给你，并总结一句「各站最终用的什么模式」，方便你发给同事。

任何变更后都跑一次 `python3 gen.py`，让 version 自增、脚本刷新。

## 生成器做了什么

`gen.py` 读 `sitelist.xml` → 把 `version` 自增 +1 → 按列表自动推导 ZoneMap 主机 → 生成 `dist/setup-ie-compat.bat`（含 Edge 企业模式策略 + Intranet 区域 + ActiveX + 重启，幂等可重跑）。`.bat` 自带自提权（双击弹 UAC），注册表 / 区域用 `/f` 覆盖，重跑安全。

安全护栏（坏输入直接拒绝并报错，绝不生成坏脚本）：

- 站点 URL 不允许含空格、引号、`;`、`\`、`<>`、`&` 等特殊字符或非 ASCII 字符（避免破坏 `.bat` 或注入命令、避免 GBK 乱码）。
- 文档模式只接受 IE8 / IE9 / IE11；打开方式只接受 IE11。
- 空列表、缺 version、非法 XML 一律中止并说明原因。

成功后打印：`version=N, sites=M, zonemap_hosts=K`。

## 导出给同事 / 团队复用

调试通过后，把 `dist/setup-ie-compat.bat` 直接发给同公司同事，他们以管理员运行即可（同批老旧站点通用）。这就是主要用法：一个人调好，团队复用。

- `.bat` 常被邮件 / IM 当高风险附件拦截：临时改后缀为 `.txt` 发过去让对方改回，或用 U 盘 / 内网共享 / 企业网盘传。
- 可转发的话术：「这是内部配置脚本，需要允许管理员运行。它只会把咱们的内网站点加进 Edge 的 IE 兼容列表，不会动其他东西，运行后重开 Edge 就行。运行前记得先保存 Edge 里没保存的内容。」

### 验证

- 主验证（面向非技术同事）：直接打开那个老系统，看能不能正常用——这是唯一可信的验证。
- 进阶（可选）：`edge://compat/enterprise` 看版本号是否 +1、站点是否列出；改完重开 Edge 仍不生效时点一次 **Force update**。

## 域环境 GPO 风险（最常见的静默失效）

如果贵司 Edge 策略由 IT 通过**组策略（GPO）统一下发**，本脚本写入的本地注册表策略**可能被 GPO 覆盖或不生效，且脚本不会报错**。遇到「跑完了但老系统还是打不对」，且在 `edge://policy` 看到策略项已显示「已设置」仍无效时，应请 IT 把内网站点加入企业模式站点列表策略。生成的 `.bat` 结尾也会提示这一点。

## 脱敏原则（重要）

- 本 skill 仓库**不含任何真实内网地址 / IP**。站点由你提供，AI 写入 `sitelist.xml`；占位示例一律用 `intranet.example.com:端口` 这类保留假域名。ZoneMap 注册表项由生成器从列表自动推导，不要手写 IP。
- `sitelist.xml` 与 `dist/` 都是**用户数据**（含真实地址），已被 `.gitignore` 排除；仓库内唯一可见样例是 `sitelist.xml.example`。**绝不要把含真实网址的 `.bat` 或 `sitelist.xml` 提交 / 发布到代码仓库或公网**——但「不发布」和「发给同事」是两件事，可以发给同公司同事。

## 注意事项

- 不要混用 `edge://compat/SiteListManager` 图形界面维护同一份列表，避免 schema 互相覆盖。
- 一次性策略（Edge 企业模式注册表、Intranet 区域、ActiveX）已并入生成的 `.bat`，重跑即刷新，无需单独维护。
- 删除 / 调整站点后重跑 `gen.py`，生成器会先清掉旧 ZoneMap 项再按当前列表重建，已删站点不再被划入 Intranet 区域。
- 面向非技术同事说话用大白话（「让老系统用哪种老 IE 内核」）；技术标签只留在内部，不必抛给对方。
